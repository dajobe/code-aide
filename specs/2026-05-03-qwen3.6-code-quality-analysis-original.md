## Critical Issues

### 1. Silent Exception Swallowing

The most dangerous pattern in the codebase. Bare `except: pass` blocks exist in
dozens of locations, making runtime failures invisible.

| File                | Lines                                                                              | Context                                                                               |
|:--------------------|:-----------------------------------------------------------------------------------|:--------------------------------------------------------------------------------------|
| `detection.py`      | 63, 141, 159, 161, 165, 199, 207, 214, 224, 229, 239, 257, 267, 286, 294, 304, 317 | `get_brew_package_info`, `get_pkg_package_info` — all error output discarded silently |
| `operations.py`     | 436-437                                                                            | `validate_tools` — bare `except Exception: pass` with no logging                      |
| `commands_tools.py` | 101-102, 110-111                                                                   | npm/node version detection — all errors suppressed                                    |
| `status.py`         | 464-465                                                                            | `get_tool_status` — version check errors silently ignored                             |

Impact: Users see incorrect status or silent failures with no way to diagnose.

### 2. Untested Critical Code Paths

| Module       | Functions                                                             | Lines | Tests                                           |
|:-------------|:----------------------------------------------------------------------|:------|:------------------------------------------------|
| `prereqs.py` | `check_prerequisites`, `install_nodejs_npm`, `check_path_directories` | 1-194 | None                                            |
| `entry.py`   | CLI argument parser, default subcommand                               | 1-115 | 1 partial test (130 lines into a 115-line file) |

The three functions in `prereqs.py` handle Node.js installation and PATH

`--yes`.

|:---------------|:--------------------------------------------------------------------------------------------------------------------------------------------------------------------|:--------|
| `upgrade_tool` | "Unknown tool", "not installed", "No npm package configured", "No FreeBSD port configured", "Package-managed tools cannot be upgraded", "Don't know how to upgrade" | 188-276 |

## Maintainability Issues

### 4. Duplicate `if/elif InstallMethod` Chains

Three functions each reimplement dispatch for every `InstallMethod`:

| Function                         | Lines         | Method Count |
|:---------------------------------|:--------------|:-------------|
| `install_tool` (`install.py`)    | 330-376 (47)  | 6 methods    |
| `upgrade_tool` (`operations.py`) | 205-268 (64)  | 6 methods    |
| `remove_tool` (`operations.py`)  | 298-417 (120) | 6 methods    |

Total: ~230 lines of duplicated branching. A single dispatch table would
collapse this.

### 5. Three Near-Identical Print Functions

In `status.py:316-432`, three functions differ only by label strings:

- `print_system_version_status` (316-338)
- `print_brew_version_status` (361-395)
- `print_pkg_version_status` (398-432)

Each ~25 lines. Should be one function with a `label` parameter.

### 7. Duplicate Regex Patterns

Version-matching pattern `[r"\d{4}\.\d{2}\.\d{2}-[0-9a-f]+",

`versions.py:65-73` and `versions.py:88-95`. The pattern `"[.\-]"` also appears
in three functions within `detection.py`.

## Correctness Risks

### 8. Incorrect Return Type Annotation

`console.py:37` declares `run_command` returns `Union[CompletedProcess,
CalledProcessError]`, but `CalledProcessError` is an exception class, never a
return value. The correct annotation should be `CompletedProcess | None`.

### 9. Hardcoded Path Separator

`prereqs.py` uses hardcoded `":"` as a path separator (TODO.md item 5). Should
use `os.pathsep`. The project classifiers list macOS, Linux, FreeBSD — not
Windows — but this is a correctness smell regardless.

## Test Quality Issues

### 11. Unsafe Test Isolation Pattern

`mock.patch.dict(..., clear=True)` is used across 10+ test files. This replaces
the production `TOOLS` dict entirely. If a test fails before restoring,
subsequent tests operate on mutated global state.

Affected tests: `test_commands_tools.py:25`, `test_install.py:78`, and others.

### 12. Untesting Modules

| Module                   | Lines | Tests   | Status                                                                                             |
|:-------------------------|:------|:--------|:---------------------------------------------------------------------------------------------------|
| `prereqs.py`             | 194   | 0       | No test file exists                                                                                |
| `config.py` (partial)    | 204   | Partial | `versions_cache_is_fresh`, `refresh_versions_cache`, `ensure_versions_cache` never called in tests |
| `status.py` (partial)    | 467   | Partial | `get_tool_status`, `print_pkg_version_status` not directly tested                                  |
| `constants.py` (partial) | 51    | Partial | `_use_color()` branches (`NO_COLOR`, `FORCE_COLOR`, `CLICOLOR_FORCE`, `TERM=dumb`) never verified  |

### 13. No Network Test Marker

`fetch_url()` in `versions.py` makes real HTTP calls via the standard library.
Without a `@pytest.mark.network` marker, these tests cannot be selectively
skipped in CI, making the test suite slow and flaky when network access is
restricted.

## Configuration Issues

### 14. Incomplete pytest Configuration

`pyproject.toml` (lines 44-45) has bare `[tool.pytest.ini_options]` with only
`testpaths`. Missing:

- `filterwarnings` — deprecation/swapping errors silently ignored
- Custom markers (e.g., `@pytest.mark.network`)
- Parallelism configuration for `pytest-xdist`

### 15. Incomplete Documentation

The `README.md` and bundled tool definitions do not document:

- `freebsd_port` and `freebsd_pkg_repo` fields (used in `install.py:298-328`,
  `detection.py:105-107`)
- `version_args` field (default `["--version"]`, used in `status.py:449`)
- `install_script_path_prepend` feature (used in `install.py:106`,
  `operations.py:232`)
